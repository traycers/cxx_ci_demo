# Bootstrap переписан как Python-контейнер, подключённый к `cxxci` — `bootstrap/` переименован в `repos/`

`bootstrap.sh` заменён на `scripts/bootstrap/` — Python-инструмент provisioning'а, собранный в образ и запускаемый через `docker compose run --rm bootstrap` — одноразовый сервис в `docker-compose.yml` под `profiles: ["tools"]`, чтобы он никогда не поднимался вместе с обычным `docker compose up`. Причина не в портируемости под окружение хоста (это отдельный, уже исправленный баг — см. переписывание `tc_post` на stdin), а в упрощении: контейнер подключается прямо к сети `cxxci`, поэтому каждый REST-вызов к GitLab/TeamCity — это обычный запрос к `gitlab`/`teamcity-server` по имени compose-сервиса, вместо прежних «соседних» контейнеров `docker run --rm --network cxxci curlimages/curl ...` на каждый вызов. Заодно полностью уходят хостовый hostname `gitlab.local`, обход ambient-прокси через `NO_PROXY` и коллизия с squid-прокси на опубликованном хостовом порту — всё это просто недостижимо изнутри сети.

Минтинг root PAT для GitLab по-прежнему требует exec внутрь контейнера gitlab (`gitlab-rails runner`, а не HTTP-вызов), а чтение super-user токена TeamCity по-прежнему требует логов этого контейнера — то и другое недостижимо через обычную сеть. Для этого сервис `bootstrap` монтирует `/var/run/docker.sock` — тот же паттерн Docker-outside-of-Docker, который уже используется у `teamcity-agent` в этом репозитории. Docker SDK для Python обращается к демону напрямую через этот сокет; в образе нет ни `docker` CLI, ни compose-плагина, а соседние контейнеры находятся по стандартной метке `com.docker.compose.service`, а не по жёстко заданному имени — так что это не зависит от `COMPOSE_PROJECT_NAME` или схемы именования контейнеров.

Переписывание заодно сменило язык: Python вместо bash, с `python-gitlab`, Docker SDK, `GitPython` и `requests` вместо голых вызовов `subprocess`/`curl` — раз образ и так собирается, читаемость настоящих клиентских библиотек ничего дополнительно не стоит. Зафиксирован Python 3.14.7 (актуальная стабильная версия на момент написания), по той же схеме точного пиннинга, что уже используется для `teamcity-server`/`teamcity-agent`, а не `:latest`.

Посевной контент копируется (`COPY`) в образ на этапе сборки, а не пробрасывается bind mount'ом — добавление новой ветки для посева (ADR 0007) теперь означает пересборку образа, осознанный компромисс ради более простого, самодостаточного контейнера, учитывая реальное назначение этого инструмента (поднять систему и продемонстрировать сборку C++, а не часто итерируемый цикл разработки).

Идемпотентность сохранена 1:1 с bash-версией: каждый REST-вызов по-прежнему проверяет состояние перед действием (существует ли VCS root? уже запушена ли ветка? уже авторизован ли агент?) — то же самое свойство «безопасно перезапускать», просто реализованное через `requests`/`GitPython` вместо вызовов `curl`/`git` через subprocess. Старый `bootstrap.sh` удалён полностью, а не оставлен рядом как запасной вариант; история git сохраняет его, если понадобится свериться.

Заодно корневая директория `bootstrap/` (посевной контент, см. ADR 0007) переименована в `repos/` — чистое переименование, без изменений в раскладке по веткам, стратегии orphan-коммитов или порядке пуша, которые установил ADR 0007. Все жёстко прописанные ссылки на старый путь (`scripts/new-release.sh`, `README.md`, `CONTEXT.md`) обновлены; сам ADR 0007 оставлен как исторический протокол этого решения, с короткой пометкой-указателем вместо правки текста на месте (та же конвенция, что и ADR 0005 → 0006).

Следствие: поднятие стенда теперь заканчивается командой `docker compose run --rm bootstrap` вместо `./bootstrap.sh`, а любой путь, который раньше читался как `bootstrap/ci-infra/...`, теперь читается как `repos/ci-infra/...`.
