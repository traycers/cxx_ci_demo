# Без Docker registry — корневая сборка образа остаётся в общем хостовом Docker-демоне

Есть ровно один build-агент TeamCity, и он делит `docker.sock` хоста для каждого запускаемого
контейнера. В обычной CI-настройке образ, собранный корневой сборкой, пушился бы в registry, чтобы
его могли забрать другие агенты/хосты.

Мы решили полностью отказаться от registry: `docker build` корневой сборки образа сразу попадает
в тот же единственный общий docker-демон, а нижестоящие сборки C++ проектов ссылаются на него по
тегу (`%build_image_cxx%`) через `docker run` — без шага push/pull.

Следствие: это работает только потому, что все сборки делят один docker-демон. Добавление
второго build-агента (горизонтальное масштабирование) потребовало бы введения registry —
известное, осознанное ограничение этого демо-стенда, а не недосмотр.

Следствие после появления релизов (см. `docs/ru/adding-a-release.md`): корневая сборка образа
каждого релиза попадает в тот же общий демон, поэтому голого тега `%build.number%` недостаточно,
чтобы их различать — два релиза могли бы независимо породить сборку номер, скажем, 12. `BuildCImage`
каждого релиза тегирует свой образ как `cxxci-build:<config_name>-%build.number%` (например,
`cxxci-build:main-106`), и каждый нижестоящий build type этого релиза строит тот же префиксованный
тег, чтобы его потребить. Registry по-прежнему нет, демон по-прежнему один — просто более широкое
пространство имён тегов.

Второе следствие: отсутствие registry означает и отсутствие garbage collection на его стороне —
любой образ, когда-либо собранный любым релизом, остаётся в общем демоне навсегда, если его
что-то явно не удалит. Подтверждено вживую: на демо-хосте накопилось 104 бесхозных тега
`cxxci-build:*`, прежде чем это было исправлено. Шаг "cleanup old images" в `BuildCImage`
(выполняется только после успешного "docker build") оставляет `%keep_images_count%` новейших
тегов для префикса собственного релиза и удаляет остальные через `docker rmi -f` — каждый релиз
чистит только свои собственные теги, никогда не трогая образы другого релиза.
