# Централизованный репозиторий CI-конфигурации (ci-infra) вместо .teamcity в каждом проекте

Идиоматичный паттерн TeamCity — versioned settings на каждый проект (папка `.teamcity` внутри
репозитория самого проекта). Вместо этого мы кладём весь Kotlin DSL — корневую сборку образа,
build configuration каждого C++ проекта и связку snapshot/artifact-зависимостей между ними — в
один центральный репозиторий `ci-infra` в GitLab, отдельно от репозиториев C++ проектов.

Мы выбрали это потому, что репозитории C++ проектов создаются независимо (часто позже, другими
разработчиками) и не должны нести на себе CI-обвязку; сборка docker-образа и топология
межпроектных зависимостей — это по своей природе инфраструктурная забота, а не забота отдельного
проекта; и — намеренно — это не даёт разработчикам менять CI-конфигурацию из репозитория своего
собственного проекта.

Следствие: добавление нового C++ проекта в дерево сборок всегда требует изменения в `ci-infra`, а
не только в репозитории самого нового проекта. Это осознанное решение, а не недосмотр.
