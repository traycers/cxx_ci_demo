# Per-branch bootstrap content — `bootstrap/<repo>/<branch>/`

`bootstrap/<repo>/` used to be flat — one directory of files per repo, pushed as the single `main` branch by `push_repo_content()`. We restructured it to `bootstrap/<repo>/<branch>/`, one subdirectory per branch, so a repo can be seeded with several pre-made branches carrying deliberately different content, not just `main`. All three existing repos (`ci-infra`, `demo-project-a`, `demo-project-b`) were migrated to this shape in the same change (their content moved to `.../main/`) rather than leaving them on the old flat layout — `bootstrap.sh` only has to support one directory shape this way.

`bootstrap.sh` discovers branches by scanning `bootstrap/<repo>/`'s subdirectories — adding a branch to seed is just adding a directory, no script change needed. Each branch is pushed as its own independent orphan commit (fresh `git init`, single commit) rather than built on top of `main`'s history: the directories hold deliberately different content by design, not a fork of one codebase, so a shared root would carry no meaning. `main` is always pushed first when present, because GitLab makes the first branch ever pushed to an empty repo its default branch — pushing it first keeps that default independent of directory-listing order. Re-running `bootstrap.sh` checks and pushes each branch independently (`git ls-remote` per branch, not once per repo), so adding a new branch directory to an already-bootstrapped repo and re-running pushes just the new branch instead of no-op'ing on the whole repo.

This is deliberately unrelated to `adding-a-release.md`'s branch-creation step: that step creates a plain git branch in an already-content-complete demo-project repo purely so a TeamCity release's VCS root has something to build (no separate content, same code as `main`) — this mechanism is for repos that need genuinely different content per branch from the start. Wiring a new repo into TeamCity itself (VCS root, build configuration in the Kotlin DSL) is out of scope here — this ADR only covers how `bootstrap.sh` gets content onto GitLab branches, not how TeamCity is told to build them.

Consequence: `bootstrap/<repo>/<branch>/.../*` paths shifted one level deeper for the three existing repos — e.g. `bootstrap/ci-infra/.teamcity/` is now `bootstrap/ci-infra/main/.teamcity/`. Anything that hardcoded the old flat path (`scripts/new-release.sh`, `bootstrap.sh`'s own log messages, this repo's `README.md`) was updated; ADR 0003/0004, which predate this change and describe an unrelated decision, were left as historical record and not retroactively edited for the path.
