# Bootstrap rewritten as a Python container attached to `cxxci` — `bootstrap/` renamed to `repos/`

`bootstrap.sh` was replaced by `scripts/bootstrap/`, a Python provisioning tool built into an image and run with `docker compose run --rm bootstrap` — a one-shot service defined in `docker-compose.yml` under `profiles: ["tools"]` so it never starts with plain `docker compose up`. The reason isn't host-environment portability (that was a separate, already-fixed bug — see the `tc_post` stdin rewrite) but simplification: the container attaches directly to the `cxxci` network, so every GitLab/TeamCity REST call is a plain request to `gitlab`/`teamcity-server` by compose service name, replacing the old script's per-call `docker run --rm --network cxxci curlimages/curl ...` sibling containers. It also drops the host-only `gitlab.local` hostname, the ambient-proxy `NO_PROXY` workaround, and the published-host-port squid-proxy collision entirely — none of that is reachable from inside the network in the first place.

Minting the GitLab root PAT still needs to exec into the `gitlab` container (`gitlab-rails runner`, not an HTTP call), and reading the TeamCity super-user token still needs that container's logs — both unreachable by plain network access. For this, the `bootstrap` service mounts `/var/run/docker.sock`, the same Docker-outside-of-Docker pattern `teamcity-agent` already uses in this repo. The Docker SDK for Python talks to the daemon over that socket directly; the image carries no `docker` CLI or compose plugin, and finds sibling containers by the standard `com.docker.compose.service` label rather than a hardcoded name, so it doesn't depend on `COMPOSE_PROJECT_NAME` or container-naming conventions.

The rewrite also moved language: Python instead of bash, using `python-gitlab`, the `docker` SDK, `GitPython`, and `requests` rather than raw `subprocess`/`curl` calls, on the reasoning that since an image is being built either way, the readability of real client libraries costs nothing extra. Pinned to Python 3.14.7 (current stable at the time), matching the exact-version pinning already used for `teamcity-server`/`teamcity-agent` rather than `:latest`.

Seed content is `COPY`'d into the image at build time, not bind-mounted — adding a new branch to seed (ADR 0007) now means rebuilding the image, a deliberate trade-off for a simpler, self-contained container given this tool's actual purpose (standing the system up and demonstrating the C++ build, not a frequently-iterated development loop).

Idempotency is preserved 1:1 with the bash version: every REST call still checks state before acting (VCS root exists? branch already pushed? agent already authorized?) — the exact same "safe to re-run" property, just implemented with `requests`/`GitPython` instead of `curl`/`git` subprocess calls. The old `bootstrap.sh` was deleted outright rather than kept alongside as a fallback; git history holds it if anyone needs to compare.

Alongside this, the root `bootstrap/` directory (seed content, see ADR 0007) was renamed to `repos/` — a plain rename, no change to the per-branch layout, orphan-commit strategy, or push order that ADR 0007 established. Every hardcoded reference to the old path (`scripts/new-release.sh`, `README.md`, `CONTEXT.md`) was updated; ADR 0007 itself was left as the historical record of that decision, with a short pointer note added rather than being rewritten in place (same convention as ADR 0005 → 0006).

Consequence: bringing the stand up now ends with `docker compose run --rm bootstrap` instead of `./bootstrap.sh`, and every path that used to read `bootstrap/ci-infra/...` now reads `repos/ci-infra/...`.
