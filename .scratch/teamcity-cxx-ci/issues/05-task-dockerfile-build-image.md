## Question

Написать Dockerfile для образа сборки C++ (попадёт в `bootstrap/ci-infra/` — см. тикет 08), на основе которого работает корневая сборка образа.

Минимально достаточно для demo: разумный современный base image (например `ubuntu:24.04`), компилятор (g++ или clang), `cmake`, `make`/`ninja`. Дополнительный пакетный менеджер (Conan/vcpkg) не нужен — inter-project зависимости решаются через artifact-зависимости TeamCity (см. `map.md`), а не пакетный менеджер.

Готово, когда образ локально собирается (`docker build`) и внутри есть всё нужное, чтобы собрать простой CMake-проект.

## Answer

`bootstrap/ci-infra/Dockerfile` — `ubuntu:24.04` + `build-essential` (g++/make), `cmake`, `ninja-build`, `ca-certificates`. Пакетный менеджер не добавлял (не нужен, см. вопрос).

Проверено локально: `docker build` проходит, внутри собран и запущен тривиальный `cmake`/`ninja`-проект (`printf("ok\n")` — вывел `ok`). Контейнер по умолчанию пишет файлы под root — на реальном TeamCity-агенте это не проблема, т.к. агент и так запускается как root (`-u 0`, см. тикет 01); на хосте это просто означало, что временную smoke-test директорию пришлось подчищать через вспомогательный контейнер, а не напрямую.

Тестовый тег `cxxci-build:test` удалён локально — реальный тег/сборка образа будет через корневую TeamCity-сборку (тикет 07), не вручную.
